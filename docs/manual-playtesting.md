# Ручной прогон без браузера

Консольный раннер запускает настоящий игровой код из `index.html` в том же лёгком окружении, что и пакетный симулятор. Он не меняет исходник на лету и не требует браузера или зависимостей. Управляющий отключён: строительство, найм, улучшения и награды решает тестировщик. Герои и враги продолжают действовать по обычным правилам. После поражения ход больше не выполняется.

## Запуск

```sh
node scripts/manual-playtest.mjs --seed 2222
```

Команды читаются по строке, ответы выдаются как JSON. Можно начать новую партию командой `new 25`, не перезапуская процесс. Без `--seed` первой командой должна быть `new SEED`. `help` печатает список команд, `quit` завершает процесс.

| Команда | Действие |
| --- | --- |
| `state` | Текущее состояние, включая экономику, героев, известные цели и события прошлого хода |
| `map [RADIUS]` | Символическая карта вокруг замка; `?` означает неизвестную территорию |
| `sites [LIMIT]` | Известные пригодные площадки: дорога, цена, доступные промыслы и доход; богатые места идут первыми |
| `step [COUNT]` | Сыграть один или несколько больших ходов; вывести события каждого и итоговое состояние |
| `build ID` | Начать постройку, например `build rogues` или `build granary` |
| `hire GUILD` | Нанять героя, например `hire rogue` или `hire ranger` |
| `upgrade` | Улучшить замок |
| `bounty explore X Y` | Поставить награду за разведку клетки |
| `bounty patrol X Y` | Поставить награду за патруль известной клетки |
| `bounty kill ID`, `bounty hunt ID`, `bounty lair ID` | Поставить награду за известную цель |
| `cancel ID` | Отменить награду и вернуть её стоимость в казну |
| `canfound X Y [SPEC]` | Проверить место деревни и варианты промысла |
| `found X Y SPEC` | Основать деревню с промыслом `fields`, `forest`, `mine` или `fish` |
| `vbuild X Y militia` | Нанять стражника в известной деревне за 20 монет на шесть ходов; повторный найм через восемь ходов после покупки. Аналогично доступны `inn` и `guardhouse` |

`result: false` или `result: null` означает, что действие сейчас недоступно. Состояние показывает только известные игроку логова, деревни и богатые места, видимых врагов, склады деревень и телеги в пути. `map` и `sites` не раскрывают туман войны; `+` на карте отмечает известное богатое место. `sites` использует ту же проверку доступности, что карточка клетки. Поле `gameOver` отмечает поражение; `step` после него вернёт пустой список ходов.
`autoSteward` должен быть `false`; `discoveredPct` — доля карты от 0 до 1.

Пример пакетного воспроизведения короткой последовательности:

```sh
node scripts/manual-playtest.mjs --seed 2222 <<'PLAY'
build rogues
step 2
hire rogue
step 1
state
quit
PLAY
```

## Как проводить сравнение

1. Записать сид, стартовые `castleAdj`, производство и расход еды, стартовые доступные постройки.
2. На каждом решении записывать намерение: почему сейчас строится здание, нанимается герой или размещается награда. После действия проверить `result` и новое состояние.
3. Двигаться по одному ходу там, где ждём событие: завершение здания, первый герой, нападение, зима, гибель, найденные руины, пригодное место деревни. `step COUNT` использовать только для спокойных промежутков; он всё равно возвращает события каждого хода.
4. Зафиксировать ход первого героя, его выживание и уровень, открытые клетки, находки, динамику еды и монет, нападения, ход первого основания деревни, первую доставку телеги или поражение. У деревни записать выбранный промысел, сезонный доход, HP и положение, HP, оставшийся срок ополченца. При проверке ополчения отдельно сравнить один сид с ним и без него, включая стоимость, разграбления и ход первой телеги.
5. Сравнить **одинаковый сид с разным порядком решений** для проверки ценности выбора игрока и **разные сиды с одинаковой стратегией** для проверки влияния карты. Не смешивать результат конкретных решений агента с поведением автоматического управляющего: в ручном прогоне он отключён.
6. Если изменение затрагивает экономику, разведку, движение, цели актёров или бой, дополнительно запускать пакетный `scripts/sim-harness.mjs` по инструкции в `AGENTS.md`.

Для обсуждения ранней игры полезны как минимум четыре сценария: ранняя гильдия и герой; сначала продовольственная деревня; исследование ради богатого места; позднее основание перед зимой. Несколько сидов и повтор одного сида с другим открытием дают больше информации, чем длинный единственный прогон.

Ограничение: раннер проверяет игровые правила и решения по ходам. Он не проверяет доступность кнопок, размеры экрана, прокрутку, анимации или отклик на касания.
